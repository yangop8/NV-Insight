## 一、NVIDIA Sentry：BlueField-4 DPU 上的 agent 运行时带外安全

【快讯内容】
NVIDIA Sentry 运行时安全框架技术详解上线：Sentry 跑在 BlueField-4 DPU 上，以 DOCA Tower（基于 Envoy + Open Policy Agent 的透明安全网关）和 DOCA Argus（带外分析主机易失内存）在 agent 与模型/外网的唯一路径上做带外监控，越界毫秒级隔离，计划明年初 GA。

【观点】
网络方向直接参考：把 agent 安全策略执行从主机 CPU 卸载到 BlueField-4 DPU 数据面，DPU 作为 agent 到模型/外网的唯一路径，天然契合零信任 AI 工厂东西向默认管控，与 09-28 Open Agent Safety Platform、03-23 Zero-Trust AI Factories 一脉相承，是 DPU 作策略执行点的又一落地。系统软件方向直接参考：DOCA Argus 带外读取易失内存、独立于被监控进程运行，规避"自证安全"悖论——即便主机侧 OpenShell 被绕过仍可观测，可回灌推理运行时的进程隔离与准入控制设计。嵌入式方向间接参考：面向数据中心 BlueField-4，端侧无直接产品，但带外硬件监控+越界即隔离的机制对安全关键边缘 agent 有方法论借鉴。

> 参考文章：[Inside NVIDIA Sentry: Secure AI Agents at Runtime](https://developer.nvidia.com/blog/inside-nvidia-sentry-secure-ai-agents-at-runtime)

## 二、NVIDIA OpenShell 参考架构：主机侧 agent 负载治理栈

【快讯内容】
NVIDIA OpenShell 参考架构技术详解上线：Apache 2.0 开源运行时把 agent 负载视为不可信，四组件 Gateway 控制面、Supervisor 出站校验与凭证中介、Sandbox 隔离、Policy Prover 形式化验证权限边界，跑在 Vera CPU 并配 BlueField DPU 上的 Sentry 做带外执行。

【观点】
系统软件方向直接参考：Sandbox 内核级隔离 + Policy Prover 对权限边界做形式化验证，为 agent 运行时提供可验证边界；CoreWeave 称 Vera 上沙箱启动较 x86 快 3 倍、单机架支持 1.1 万+并发 agent 环境，印证把治理栈下沉到 CPU/DPU 的性能收益，可回灌 vLLM/SGLang 的进程隔离与沙箱化准入控制。与 09-28 Open Agent Safety Platform 同体系、不同 URL——此篇聚焦主机侧（Vera CPU）治理栈四组件，与同日 Sentry 专篇（DPU 带外执行）互补。网络方向间接参考：BlueField DPU 承载 Sentry 作为架构的带外执行点。嵌入式方向间接参考：面向数据中心 Vera CPU，端侧无直接部署。

> 参考文章：[How NVIDIA OpenShell Reference Architecture Secures and Governs AI Agent Workloads at Scale](https://developer.nvidia.com/blog/how-nvidia-openshell-reference-architecture-secures-and-governs-ai-agent-workloads-at-scale/)
