## 生成式推荐（GR）重塑大规模 RecSys：recsys-examples + nv-embedding-cache

【快讯内容】
NVIDIA 阐述生成式推荐（GR）如何重塑大规模 RecSys：以 HSTU 把推荐改为"按用户历史序列预测下一物品"的生成目标；开源 recsys-examples（DynamicEmb 打分哈希嵌入、推荐专用 KV cache、融合 CUDA 内核、Megatron-Core/TorchRec 并行）与分层多级缓存 nv-embedding-cache（分片+并发查/逐出），在 DLRM v3（MLPerf）在线服务达约 10 万 queries/sec。

【观点】
系统软件方向直接参考：GR 把 RecSys 的核心负载（长输入序列、注意力密集、超大嵌入表）与 LLM 推理栈对齐——DynamicEmb 主机内存打分哈希表 + 推荐专用 KV cache + 融合 CUDA 内核把训练/推理内核化，nv-embedding-cache 的分层多级缓存与并发查/逐出，是超大嵌入表低延迟高吞吐服务的关键设计，可直接借鉴到向量检索、KV 复用、显存-主存分层的推理引擎。网络方向间接参考：嵌入表分片与集合通信路径对多节点 embedding 分布有参考。嵌入式方向无直接参考价值。

> 参考文章：[How Generative Recommenders Are Redefining RecSys at Scale](https://developer.nvidia.com/blog/how-generative-recommenders-are-redefining-recsys-at-scale)

## cuML/cuVS 多 GPU UMAP：分簇-局部-合并规避 all-to-all，8×H100 提速 74x

【快讯内容】
NVIDIA cuML/cuVS 25.06 为 UMAP 的全邻居 kNN 图构建引入多 GPU 支持：把数据集划分为均衡簇、各簇独立算局部 kNN 图再合并为全局图，避免 all-to-all 通信且保持嵌入质量；8×H100 上对 MIRACL/Wiki 较投影 CPU 运行提速至多 74x，trustworthiness 可信度分数保持高位，把数亿向量/数百 GB 的 UMAP 降到分钟级。

【观点】
系统软件方向直接参考：communication-avoiding 的多 GPU 图构建（分簇→局部计算→合并、规避 all-to-all）是分布式算法降低通信瓶颈的范式，对多卡数据科学与向量索引内核扩展有直接借鉴；以 trustworthiness 作为质量守恒指标，把"加速不掉精度"量化为可回归约束。网络方向间接参考：显式规避 all-to-all 的设计正回应大规模并行的通信墙问题，对集合通信拓扑权衡有参考。嵌入式方向无直接参考价值。

> 参考文章：[Run Massive-Scale UMAP in Minutes Using Multiple GPUs—Without Losing Accuracy](https://developer.nvidia.com/blog/run-massive-scale-umap-in-minutes-using-multiple-gpus-without-losing-accuracy)
