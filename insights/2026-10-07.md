## 1. DOCA GPUNetIO 统一全栈 GPU 发起式网络

【快讯内容】
NVIDIA 发文阐述 DOCA GPUNetIO 如何把 GPUDirect RDMA、GPUDirect Async Kernel-Initiated（GDA-KI）与 GDRCopy 整合为统一基座，让 CUDA kernel 直接驱动以太网、RDMA、Verbs 与 DMA，将 CPU 移出应用关键路径。NCCL、NVSHMEM、UCX/NIXL、Holoscan Sensor Bridge 现均基于该共享 GPUNetIO 实现，不再各自维护独立 GDA-KI。

【观点】
网络方向直接参考：GPU 发起式通信把网卡控制权从主机下沉到 CUDA kernel，消除 CPU 在收发关键路径上的中介延迟，是低延迟 RDMA/以太网与分布式推理 all-to-all 的底层杠杆；集合通信库（NCCL/NVSHMEM）与 KV 路由（NIXL/UCX）收敛到同一 GDA-KI 基座，利于 fabric 侧统一调优与精确发包调度。系统软件方向直接参考：多库共用单一基座降低跨栈维护与互操作成本，内核直驱 DMA/网卡为推理引擎 kernel 级编排提供可复用原语。嵌入式方向间接：Holoscan 传感器桥同源，边缘实时网络处理可共享栈。

> 参考文章：[How DOCA GPUNetIO Unifies GPU-Initiated Networking Across the NVIDIA Software Stack](https://developer.nvidia.com/blog/doca-gpunetio-gda-ki-unified-gpu-networking)

## 2. Green Contexts：GPU 资源细粒度空间划分

【快讯内容】
NVIDIA 介绍 Green Contexts——轻量级 CUDA 上下文，可将 SM 与工作队列按需划分给不同组件，使延迟敏感算子与吞吐型后台 kernel 在单进程内互不干扰。Driver API 自 CUDA 12.4 起提供，CUDA 13.1 起经 Runtime API 可用；无需改 kernel，仅需少量 host 侧改动。实测 Blackwell（148 SM）上延迟敏感 kernel 时延由 0.140ms 降至 0.007ms。

【观点】
系统软件方向直接参考：Green Contexts 以空间划分替代纯时间片抢占，为单 GPU 多负载共置提供确定性 SM 配额——可保障推理 SLA 的延迟敏感路径始终有 SM 可用，同时让预处理/后台 kernel 吞吐隔离，是 vLLM/SGLang/TensorRT-LLM 在多租户/多阶段流水线下做 QoS 与资源封顶的底层原语；opt-in、增量可采纳，便于渐进式接入。嵌入式方向间接：端侧单 GPU 跑多模型/多阶段时可用同机制保实时任务抢占确定性。网络方向无直接参考价值。

> 参考文章：[Control How Your GPU Shares Work with Green Contexts](https://developer.nvidia.com/blog/control-how-your-gpu-shares-work-with-green-contexts/)
