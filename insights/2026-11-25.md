## 1. Cosmos 3 Nano 端侧视频生成：Diffusers 流式卸载 + FP8 分段量化

【快讯内容】
Cosmos 3 Nano 世界基础模型经 Hugging Face Diffusers 流式适配器落地消费级 RTX（5070~5090）：权重常驻系统内存、按 Transformer 块经 PCIe 流入 GPU，FP8 混合精度（首尾步 W8A16、中段 W8A8、注意力 BF16），依分辨率/模态/显存自动切换内存模式。

【观点】
嵌入式方向直接：这是"用系统内存与 PCIe 带宽换显存"的端侧大模型部署范式，把量化（FP8 W8A8/W8A16 分段）与块级流式卸载、动态内存模式结合，使 12GB 卡也能跑世界模型。代价是无交互延迟（720p 约 44 分钟），说明当前端侧生成式部署仍偏离线批处理；且仅覆盖 RTX 桌面卡，未触及 Jetson 等真边缘设备。系统软件间接：Model Optimizer 量化 + 块级调度是端侧推理工程重点。网络无直接。

> 参考文章：[How to Run NVIDIA Cosmos 3 on Local AI Devices Using Hugging Face Diffusers](https://developer.nvidia.com/blog/how-to-run-nvidia-cosmos-3-on-local-ai-devices-using-hugging-face-diffusers/)

## 2. Science per Joule：从吞吐转向"能效到解"的性能度量方法论

【快讯内容】
NVIDIA 提出"每焦耳科学产出"能效度量（原子步/焦、模拟天/焦、设计/kJ），取代 FLOPS/W 与 PUE。GB200 NVL72 系统级能效较 HGX H100 在 LAMMPS 高 9~17%、ICON 气候高约 20%；建议按设施/系统/节点/作业/产出五层测量，工具含 DCGM、nvidia-smi、DSX MaxLPS。

【观点】
系统软件直接：把性能分析从吞吐转向"能效到解"——相位对齐测量、作业级遥测、区分空闲/活跃功耗（八卡一忙时空闲+平台占 80~86%）、额定功率虚高 13~77%，直接指向动态功率管理与功率封顶调度。网络间接：ICON 在 GB200 NVLink 域 halo 交换耗时少 26%、NVSwitch 约占机架 7% 功耗，印证 scale-up 互联同时影响能效与通信开销。嵌入式无直接。

> 参考文章：[Connecting Energy Use to Scientific Output with Science per Joule](https://developer.nvidia.com/blog/connecting-energy-use-to-scientific-output-with-science-per-joule/)

## 3. Sirius：GPU 原生 SQL 引擎以"核心扩展"形态嵌入 DuckDB

【快讯内容】
NVIDIA 与 DuckLabs 将 GPU 原生 SQL 引擎 Sirius 作为 DuckDB 核心扩展发布：INSTALL/LOAD 即用、自动选 CUDA 后端，DuckDB 解析优化、Sirius 在 GPU 执行计划，不支持查询回退 CPU、SQL 无需改写。TPC-H 类查询双 GPU 较最优 CPU 加速 3.25~5.5×、算力成本降约 71~79%。

【观点】
系统软件直接：Sirius 以"核心扩展 + 计划级接管 + CPU 回退"方式把 GPU 加速嵌入现有引擎，应用接口零改动即获数据分析提速，是 GPU 下沉到通用 SQL 栈的务实路线。值得关注的工程点：大规模（SF10K）默认双 GPU 配置跑不完、必须调参，说明 GPU 数据引擎在内存管理/溢出上仍需人工干预；基准排除结果导出，实测增益需按查询结构折算。网络、嵌入式无直接参考价值。

> 参考文章：[Get Started with GPU-Accelerated DuckDB Analytics Using the Sirius Core Extension](https://developer.nvidia.com/blog/get-started-with-gpu-accelerated-duckdb-analytics-using-the-sirius-core-extension/)

## 4. cuDSS 1.0：混合内存把"显存容量墙"转为 host-device 搬运问题

【快讯内容】
NVIDIA 稀疏直接求解器 cuDSS 1.0 发布（生产级）：含重排序/符号/数值分解与三角求解，对称不定系统默认 MC64 匹配缩放 + Bunch-Kaufman 主元。混合内存模式把因子数据分放 CPU DRAM 与 GPU HBM，大型 VLSI 案例平均降约 30% 最小显存，使原需多 GPU 问题单卡（H100/B200/Vera Rubin）可解；较 MKL 三角求解约 151×。

【观点】
系统软件直接：亮点不在峰值加速而在内存工程——混合内存模式借 CPU DRAM（节点 512GB~2TB）+ pinned 内存句柄 + 主机符号分解，把"显存容量墙"转成 host-device 数据搬运问题，让大稀疏系统免分区在单 GPU 整体求解。这与近期 DGX Spark、cuPotential 等"统一内存 + 主机卸载"思路一脉相承，是 CAE/EDA 商用软件 GPU 化的关键使能。网络、嵌入式无直接。

> 参考文章：[Accelerating Direct Sparse Solvers for Computational Engineering with NVIDIA cuDSS 1.0](https://developer.nvidia.com/blog/accelerating-direct-sparse-solvers-for-computational-engineering-with-nvidia-cudss-1-0/)

## 5. Megatron Core 市场数据预测：训练栈数据面复用范式

【快讯内容】
NVIDIA 示例用 Megatron-LM 训练栈做盘中市场数据预测：Parquet 行情预处理成 patch（8 根/patch、32 patch 上下文），输出 mmap 张量文件；torchrun 四卡 BF16 训练，张量并行组内 rank0 读微批后广播，按日期切分 + 禁运期防泄漏。为验证流水线的 4 层小模型，未报吞吐/精度。

【观点】
系统软件相关：示例本身是金融教程，但其数据面做法有系统价值——内存映射张量文件按需拷贝、TP 组内 rank0 读取并广播微批、复用 Megatron 采样器与检查点，体现"把解析/目标构造移出训练循环、I/O 与并行解耦"的工程范式。可替换任意符合接口的 MegatronModule，适合快速搭建垂域预测原型。属训练栈数据流水线复用，非新调度能力；网络、嵌入式无直接。

> 参考文章：[Prepare Market Data for Forecasting with NVIDIA Megatron Core](https://developer.nvidia.com/blog/prepare-market-data-for-forecasting-with-nvidia-megatron-core/)
