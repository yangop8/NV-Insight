## 1. NVIDIA Run:ai 作为 DSX AI 工厂平台一部分全面开源

【快讯内容】
NVIDIA 将 Run:ai 平台完整开源（纳入 DSX AI 工厂平台），拆为四个可独立采用的组件：KAI Scheduler（GPU 感知 K8s 调度，已入 CNCF Sandbox）、GPU Fractioning Operator（CUDA 原生 GPU 切分）、KAI Resource Management（组织级配额/层级）、Workload Map（统一工作负载契约），源码托管于 DSX AI Factory GitHub，Crusoe/Mirantis/Nebius 等八家集成。

【观点】
系统软件：把 GPU 调度、细粒度切分、配额与工作负载抽象整栈开源，等于将 AI 工厂控制面原语公开——KAI Scheduler 的 GPU 感知装箱、Gang 调度与 GPU Fractioning 的 CUDA 原生分片，对多节点/多租户 GPU 编排与自研 K8s 调度器有直接参考，可与此前 Green Contexts（SM 空间划分）、DSX 集群就绪引擎组成从硬件配额到集群控制面的完整开源栈；网络间接（拓扑感知调度影响集合通信布局），嵌入式无直接。

> 参考文章：[NVIDIA Run:ai Is Now Open Source as Part of NVIDIA DSX AI Factory Platform](https://developer.nvidia.com/blog/nvidia-runai-is-now-open-source-as-part-of-nvidia-dsx-ai-factory-platform/)

## 2. 用 AI 智能体把 Apache Spark UDF 重写为 GPU 加速实现

【快讯内容】
NVIDIA 发布用 AI 编码智能体把 Spark UDF 迁移到 GPU（cuDF 插件）的工作流：UDF 打断声明式抽象、迫使 GPU 流水线回落 CPU 并产生搬运开销；按复杂度分三档重写（Spark SQL 表达式 / RapidsUDF+cuDF Java API / JNI 调用自定义 CUDA kernel）。开源 cudf-spark skills 覆盖测试生成、转换、基准与迭代优化；某客户改写 30+ 生产 UDF，单算子 274.55→12.78 小时（约 22x）、影响 3000+ 作业。

【观点】
系统软件：直击「UDF 黑盒打断列式 GPU 执行」这一数据处理加速顽疾——以结构化 skills 约束智能体在三档抽象间择优重写，并用生成测试+基准做可验证闭环，是「智能体+结构化约束做系统级代码生成/移植」范式的又一落地（延续 DOCA Agent Skills、cuTile Python→Rust 一脉），对自研 GPU 算子迁移、JNI/CUDA kernel 封装与大规模 ETL 加速有直接参考；网络无直接，嵌入式无直接。

> 参考文章：[How to Rewrite Apache Spark UDFs for GPU Acceleration with AI Agents](https://developer.nvidia.com/blog/rewrite-apache-spark-udfs-gpu-acceleration-ai-agents/)
