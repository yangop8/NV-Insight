## 1. NVFP4 注意力的"寄存器复用"：在 RTX Blackwell 上重叠 Tensor Core 与 Softmax

【快讯内容】
NVIDIA 在 FlashInfer 的 SM120 NVFP4 注意力内核中引入"寄存器复用"：把 128 列分数块拆成两个 64 列半块，一半经指数化并量化为 NVFP4 后立即复用其寄存器计算下一块 QK，使下一块矩阵乘与当前块的 Softmax/PV 重叠，减少 Tensor Core 空转。RTX PRO 6000 Blackwell 上内核级提速 1.17~1.64×，端到端延迟降约 1.1~15.3%。

【观点】
系统软件方向直接：这是推理引擎内核优化的典型案例——瓶颈不在算力而在寄存器文件（原已 95% 满、无法放第二块分数），靠"半块流水+寄存器回收"消除 Tensor Core 在 Softmax 期间的空闲，而非堆硬件；已并入 FlashInfer 主干，可直接用于自研推理栈。嵌入式方向直接：面向 RTX PRO 6000 Blackwell 工作站卡，NVFP4（4-bit 浮点）把 QK/PV 两段矩阵乘降到 4 位、配两级缩放补偿 Softmax 概率的窄 [0,1] 动态范围，是端侧/工作站长序列（4K~16K token）生成式推理的省显存+提吞吐路径，延续 11-25 Cosmos 3 端侧量化主线。网络无直接。

> 参考文章：[How to Optimize NVFP4 Attention on NVIDIA RTX Blackwell Through Register Recycling](https://developer.nvidia.com/blog/how-to-optimize-nvfp4-attention-on-nvidia-rtx-blackwell-through-register-recycling/)

## 2. Mission Control 管理液冷 AI 工厂：IT-OT 联动的漏液策略与遥测

【快讯内容】
NVIDIA Mission Control 打通 IT（算力/作业）与 OT（供电/冷却/楼宇安全），支持 GB200/GB300 NVL72，经 Base Command Manager 配置。漏液响应按"楼宇→房间→排→机架→设备"分层策略：单设备漏液隔离并断电整托盘，单排≥3 机架漏液则关停该排电与冷却并由 BMS 关阀。遥测经 MQTT（1883，证书认证）对接 BMS，指标以 Prometheus/Grafana 暴露（供回水温、流量、压差、机架功率对预算、CDU 健康、隔离状态）。

【观点】
系统软件方向直接：把运行时故障隔离从"作业级重启"扩展到"设施级联动"——漏液/功率异常触发节点隔离、断电、关阀的分层声明式策略，正是多节点调度与运行时安全（隔离/关停）在物理层的延伸，延续 Mission Control 2.5 自愈（10-27）主线，对自研训练/推理栈的断点续训与节点下线有借鉴。网络方向间接：MQTT 对接 BMS + Prometheus 遥测把冷却/电力纳入可观测闭环，与零信任 AI 工厂的集中认证（Keycloak）、链路遥测理念一致，但本篇偏设施网络而非数据面互联。嵌入式无直接：面向数据中心液冷机架，非端侧设备。

> 参考文章：[Manage Liquid-Cooled AI Factories with NVIDIA Mission Control](https://developer.nvidia.com/blog/manage-liquid-cooled-ai-factories-with-nvidia-mission-control/)
