## 1. FLUX 3 Image Klein 上 Blackwell 推理加速：TensorRT LLM VisualGen 以 NVFP4 量化+融合内核+torch.compile 叠加 Cache-DiT 步缓存与多卡并行，单 B200 全栈最高 3.46x

【快讯内容】
NVIDIA 技术博文（约 11-06）给出 FLUX 3 Image Klein（FLUX.2 [klein] 4B 开放权重，可于 8GB 级 GPU 运行）在 Blackwell 上的推理优化方案。TensorRT LLM VisualGen 以 NVFP4 量化+融合 PrimsTS GEMM 内核+torch.compile，单 B200 较 BF16 文生图至 1.62x、图生图至 1.58x；Cache-DiT 步缓存在 2048×2048 下近乎腰斩延迟（至 1.94x）；8 卡 B200 并行把 Base 文生图中位延迟从 14.90s 降至 3.00s；全栈叠加单 B200 文生图至 3.46x、图生图至 4.45x（均 NVIDIA 自报）。

【观点】
本篇虽以图像生成（扩散模型）为载体，但核心内容落在系统软件方向——推理引擎内核优化与模型量化，具直接参考价值。可拆为四层正交优化栈：①NVFP4 低精度量化把 Blackwell 第五代 Tensor Core 的 FP4 吞吐用满、同时以融合 GEMM 内核压缩算子间访存与启动开销，②torch.compile 做图编译消除 Python 调度与 kernel launch 碎片，③Cache-DiT 在扩散采样的时间步维度做激活/特征复用（步缓存），用「跨步冗余」换算力——这是区别于 LLM KV-Cache 的另一类缓存范式、对任何迭代式推理（扩散/多步采样/链式解码）都有方法论借鉴，④多卡张量并行把单请求延迟进一步切分、依赖 NVLink 高带宽域承接激活的 all-to-all/all-reduce（网络间接关联）。四层可叠乘且边际递减，提示自研推理栈宜「量化→编译→算法级缓存→并行」分层拉满而非单点优化。嵌入式方向间接参考——klein 4B 开放权重定位 8GB 级消费/边缘 GPU，NVFP4 把扩散生图下沉受限显存设备，与端侧多模态部署的量化预算对位；但数据中心 8×B200 场景与端侧无直接产品对应。网络方向仅间接——多卡并行的 NVLink 带宽依赖。注意：所有加速倍数均为 NVIDIA 就特定模型/分辨率/批量的自报数据、无独立基准，1.62x（单技术）与 3.46x（全栈叠加）口径不同不可混用；本篇与 11-07 登记不成篇的 FLUX.2 NVFP4 推理篇（topic 358375）为不同 URL/不同模型批次，本篇（topic 388239）系本窗口净新增、且 TensorRT LLM VisualGen 工具链叙事使其系统软件参考价值高于前者，故成篇。（图像生成模型命名在各来源不一致——NVIDIA 模型卡作「FLUX.2 [klein]」、博文标题作「FLUX 3 Image Klein」，具体以 NVIDIA 官方页面为准。）
