## 1. CUDA Toolkit 13.5 为 Vera Rubin 架构正式 GA：cuBLAS 加速 NVFP4/MXFP8 矩阵乘，补齐下一代 GPU 的编译-算子-驱动链路

【快讯内容】
NVIDIA 11-04 发布 CUDA Toolkit 13.5，正式 GA 支持 Vera Rubin GPU 架构。cuBLAS 在 Vera Rubin 上加速 NVFP4/MXFP8 矩阵乘、在 B200 上把 FP64 对称更新提速至 1.5x；新增批量 1D 内存拷贝的 CUDA Graph 支持、CUDA-GDB 可在驱动日志事件处断点、CCCL 3.5 公开 CUB 调优 API；Windows on Arm 支持延伸至 DGX Station for Windows。据二手源随附 620.70.06 Linux 驱动。

【观点】
系统软件方向直接参考——本篇是 GPU 驱动/工具链与科学计算内核对下一代硬件的适配里程碑：Vera Rubin 从 13.4 的 Developer Preview 编译目标升级为 13.5 的生产级 GA，意味着自研训练/推理栈可正式按 Rubin 代编译落地。价值集中在三处：①cuBLAS 对 NVFP4/MXFP8 低精度矩阵乘的内核优化直接服务推理引擎的 FP4/FP8 GEMM 路径（vLLM/SGLang/TensorRT 的低精度算子将直接受益），延续 10-27 Nemotron 3.5 Lightning NVFP4+QAD 的低精度推理主线；②批量 1D 拷贝的 CUDA Graph 支持降低 launch 开销、CUDA-GDB 驱动日志事件断点强化系统级调试与故障定位，契合系统级性能分析与运行时诊断；③CCCL 3.5 公开 CUB 调优 API 便于自研内核做架构自适应调优。本篇与 11-03 追踪的 AICR Vera Rubin NVL72 K8s 配方（验证用 R615.23 开源驱动分支）同属「Rubin 代硬件就绪」脉络——前者解决编译器/运行库/算子层 GA，后者解决集群调度就绪，二者共同构成自研平台适配 Rubin 的编译-算子-驱动-调度完整链路。网络方向间接——Vera Rubin 平台含 NVLink 6 / ConnectX-9 SuperNIC / BlueField-4，但本篇聚焦编译工具链本身，未涉及网络 fabric 调优，仅间接相关。嵌入式方向间接——Windows on Arm 延伸至 DGX Station for Windows 属桌面/工作站级，端侧 Jetson 无直接产品，但 Arm 平台 CUDA 支持的扩展对嵌入式 Arm 工具链演进有方法论参考。（注：cuBLAS NVFP4/MXFP8 与 B200 FP64 1.5x、CUDA Graph/CUDA-GDB/CCCL 3.5 及 620.70.06 驱动等均出自官方博文经 Developer Forums topic 388008、daily.dev、borecraft 交叉核对，具体数字与驱动最低版本以 NVIDIA CUDA 13.5 官方发行说明为准。）

## 2. NVIDIA 公开内部「AI Factory Operations Agent」：K8s 控制面 + MCP 多子代理 + 本地 Nemotron，把 DGX SuperPOD 运维推向代理化自愈

【快讯内容】
NVIDIA 11-05 公开其内部「AI Factory Operations Agent」，用于精简自家 DGX SuperPOD 运维、减轻 SRE 人工值守。该系统基于 NemoClaw 蓝图 + NVIDIA OpenShell，全程本地运行本地部署的 Nemotron 开源模型，作为 Kubernetes 控制面应用部署于内部 DGX H100/B200/GB300 生产集群；由 Job Recovery、Hardware、Observability、Research、Kubernetes、Cluster Management 等专用子代理经 Model Context Protocol（MCP）协作。编排框架以实验性开源软件发布，API 与部署要求可能变动。

【观点】
系统软件方向直接参考——这是把数据中心运维（SRE/AIOps）自主化的参考实现，恰好补齐此前追踪的韧性主线：作为 K8s 控制面应用，以 MCP 协调「作业恢复/硬件/可观测/研究/K8s/集群管理」多子代理，构成「观测—归因—恢复」的智能体编排自愈闭环，与 10-22~10-24 Minerva 可观测性、11-03 Attribution 根因定位与 NVIDIA Recovery 自动续训、10-27 Mission Control 2.5 自主恢复形成同一演进脉络的「代理化运维层」。架构上两点对自研栈有直接借鉴：①全程本地部署 Nemotron 开源模型 + OpenShell 沙箱运行，契合运行时安全（沙箱/进程隔离）与数据不出域的治理要求；②子代理按职责解耦、以 MCP 统一协议互联，对自研训练/推理平台的 SRE 自动化、故障自愈编排、本地 LLM 代理治理提供可复用范式，且框架已实验性开源可直接参考 orchestration 实现。网络方向间接——Hardware/Observability 子代理涉及互联域健康与遥测，节点隔离/下线需与 fabric 健康判定协同，属网络遥测与故障域隔离的间接关联。嵌入式方向间接——本篇面向数据中心 DGX 集群、无端侧产品，但「本地小模型 + MCP 多代理 + OpenShell 沙箱」的轻量自治架构对边缘集群/端侧联邦场景的自治运维有方法论借鉴。（注：NemoClaw/OpenShell/本地 Nemotron、K8s 控制面、DGX H100/B200/GB300、六类子代理与 MCP 协作、实验性开源等出自官方博文经 hyper.ai、daily.dev、Blockchain.News 及 GitHub NVIDIA/AI-Factory-Operations-Agent 仓库交叉核对，具体以 NVIDIA 官方页面及仓库发行说明为准。）
