## 1. Rubin HPC：面向科学/工程/分析的「数据搬运与算力同扩」GPU

【快讯内容】
SC26 发布 Vera Rubin 平台新成员 Rubin HPC GPU：单卡逾 5 万 CUDA 核（号称创纪录）、配第 7 代 NVLink，并以「稀疏数据加速」在取数阶段喂满核心、减少等待。针对稀疏矩阵、模板计算（stencil）、排序与归约等模式，瞄准气候、工程仿真、基因组、金融风险等 HPC 负载，预计 2028 年上市。

【观点】
系统软件方向直接参考——传统 HPC GPU 堆 FP64 算力，Rubin HPC 的叙事转向「数据移动与计算同比例扩展」：稀疏矩阵/stencil/排序归约都是访存受限、非规则访问模式，瓶颈在喂数而非算，故硬件级稀疏取数 + 第 7 代 NVLink 把 scale-up 带宽作为一等优化对象，延续 11-07「每字节产出最大化」全栈协同主线。对自研科学计算/图分析内核，提示优化重心从峰值 FLOPS 转向有效带宽与数据局部性。网络方向间接——NVLink 7 是 scale-up fabric 代际升级，承接稀疏负载的不规则集合通信；嵌入式无直接产品（数据中心级，2028 远期）。

> 参考文章：[NVIDIA Announces Rubin HPC — A New GPU to Accelerate Agents for Science, Engineering and Analytics](https://blogs.nvidia.com/blog/rubin-hpc/)

## 2. MLPerf Endpoints v1.0：Vera Rubin NVL72 每千瓦吞吐达 GB300 的 10×

【快讯内容】
新基准 MLPerf Endpoints v1.0 衡量智能体负载下「服务容量 vs 响应性」的平衡，经 API 端点跑编码/企业工作流，并用 SWE-bench Verified 校验加速不损质量（上下文从首响约 3 万 token 增至第 300 响约 20 万）。初步结果：在 50 tok/s/用户的最低交互性下，Vera Rubin NVL72 每千瓦吞吐达 GB300 NVL72 约 10×（Kimi K3；另 DeepSeek-V4.1-Flash 9×、Qwen3.6 5×）。

【观点】
系统软件方向直接参考——这是推理引擎内核优化 + 多节点调度的集大成：关键不只在 Rubin 硬件（HBM4/第 6 代 NVLink），更在服务软件栈——Dynamo 路由、前缀缓存/状态复用、prefill-decode 分离解耦（disaggregated serving）各自独立优化，叠加 DeepSeek MegaMoE 内核、Qwen 多 token 预测 + Tensor Core 验证。对自研推理平台，提示「长上下文智能体」才是真实压测场景，吞吐须与端到端交互性、任务正确率联合度量。网络方向间接——分离式服务把 KV/激活流量压在 NVLink 与 fabric 上。注意：Vera Rubin 为 provisional 结果待 MLCommons 核验，GB300 已核验。

> 参考文章：[NVIDIA Vera Rubin NVL72 Leads Agentic Inference Performance on MLPerf Endpoints v1.0](https://developer.nvidia.com/blog/nvidia-vera-rubin-nvl72-leads-agentic-inference-performance-on-mlperf-endpoints-v1-0/)

## 3. Nemotron 科学域后训练：实验数据即奖励的 RLVR 闭环

【快讯内容】
教程给出把 Nemotron 3.5 Super VL 后训练到科学领域（分子属性推理）的配方：将实验记录（如含 SMILES 的 CSV）转成提问/答案对，构成「可验证奖励强化学习」（RLVR）环境——奖励来自数据而非人工标注（如 Morgan 指纹 Tanimoto 相似度）。经 NeMo Gym 搭环境、NeMo RL 跑 GRPO+LoRA（16 GPU 多节点、vLLM rollout）。MetxBioDB 上 SFT 提升 12%、RL 再加 17%。

【观点】
系统软件方向直接参考——这是「推理引擎 + 训练栈」协同的智能体可靠性工程：RLVR 把领域客观指标直接做成奖励函数，绕开人工标注瓶颈，延续 11-09 NeMo「失败即测试」harness 主线；全栈（NeMo Gym/RL + Megatron 引擎 + vLLM rollout + Transformer Engine）构成可复现的本地后训练流水线，对自研垂域模型微调/RLHF 编排有直接借鉴。嵌入式方向间接——可本地运行、蒸馏（示例用 Claude Sonnet 5.5 生成推理轨迹暖启动）压低模型规模，为端侧垂域小模型提供上游。网络方向无直接关联。

> 参考文章：[Post-Training NVIDIA Nemotron to Increase Accuracy in Your Scientific Domain](https://developer.nvidia.com/blog/post-training-nvidia-nemotron-to-increase-accuracy-in-your-scientific-domain/)

## 4. DGX Spark HPC 开发者套件：四节点 ConnectX-7 无交换机环

【快讯内容】
SC26 推出 DGX Spark HPC 开发者套件：四台 DGX Spark（GB10）以 ConnectX-7 直连成环、无需交换机，合计 512GB 内存 + 16TB NVMe，可本地跑至 700B 参数（NVFP4）模型。面向有固定算力配额、不愿排队共享集群、需把未发表数据留在本地的研究者；支持 LAMMPS+Kokkos、NAMD 等多节点仿真，HPC SDK（GPU 编译器 + MPI 工具）playbook 即将推出。

【观点】
嵌入式与网络方向双重参考——「桌面级多节点」继续下沉：ConnectX-7 点对点成环、去交换机拓扑，是端侧/边缘集群低成本横向扩展的范式，呼应 11-15 双 DGX Station ConnectX-8 RDMA 跑 753B GLM-5.3，共同指向「RDMA/高速网卡 + 张量/数据并行」在桌面侧的价值延伸——互联带宽/延迟与无交换机环拓扑直接决定多节点 MPI/集合通信可扩展性。嵌入式方向可关注 GB10 统一内存四节点做 HPC 原型「先调试后上规模」的工作流，以及端侧敏感数据不出域。系统软件方向间接——HPC SDK + MPI 多节点调试链路。

> 参考文章：[NVIDIA DGX Spark Developer Kit Turns a Desk Into a Supercomputing Lab](https://blogs.nvidia.com/blog/dgx-spark-hpc-developer-kit/)

## 5. SC26 主题演讲：Photonics 共封装光学交换机早期部署（网络直接）

【快讯内容】
Ian Buck 开启 NVIDIA SC26 周，宣布系列科学 AI 进展，其中网络相关最直接：NVIDIA Photonics 共封装光学（CPO）交换机已在 Lambda 早期部署，宣称误码率与链路抖动（bit errors/link flaps）可靠性提升 15×。另有 Vera CPU 进入德国 DKRZ HLRE-5 超算（预计 2028 初）、IBM×Fermilab 量子-经典协同平台、CUDA-Q 新增「魔法态培育」与 TCBP-JOBS 解码（纠错研究 12 周→45 分）、Nsight AI 移植代理把 WRF 例程 GPU 化提速 5×+。

【观点】
网络方向直接参考——CLAUDE.md 重点关注的 CPO/硅光子技术迎来真实部署信号：CPO 把光引擎与交换 ASIC 共封装，省去可插拔光模块的电-光转换与连接点，正是「15× 更少误码/链路抖动」的物理来源；对超大规模 AI 工厂而言，链路稳定性直接决定长训练作业的 MTBF 与集合通信有效带宽，是 Spectrum-X Photonics 从发布走向规模落地的关键里程碑（延续产品线基线）。系统软件方向间接——Nsight AI 移植代理把遗留 HPC 代码自动 GPU 化，是「代理化系统软件工程」又一落点；CUDA-Q 纠错算法把研究计算量压缩数个量级。嵌入式方向无直接产品。
