## 1. Vera CPU 存储基准：AI 原生存储的数据保护流水线加速

【快讯内容】
NVIDIA 发布 Vera CPU 存储基准：较 x86 加密 1.43x、Reed-Solomon 恢复 3.26x、CRC32C 校验 3.67x、压缩 3.29x、多级流水线 3.21x，为 agentic AI 的 KV 缓存复用与持久化记忆等 AI 原生存储原语在更低功耗散热下加速。

【观点】
- **系统软件**：存储已成为 agentic 工作流一等公民——知识检索、持久化记忆、KV 缓存复用、工具执行全部落到存储 I/O。加密/校验/恢复/压缩这些原语必须在后续处理前快速完成，且跨大量并发流反复搬运数据，Vera 统一架构把它们收进更低 CPU/功耗/散热包络，直接抬高推理引擎的 KV 上下文重建与检查点吞吐、服务密度。
- **网络**：可预测低时延同带宽同等重要，存储数据面与集合通信、GPUDirect Storage 直取路径协同，决定分离式服务下 KV/权重跨节点搬运的尾时延边界。
- 嵌入式无直接参考价值。

> 参考文章：[NVIDIA Vera Storage Benchmarks: Faster Encryption, Compression, Integrity Checking, and Recovery for AI-Native Storage](https://developer.nvidia.com/blog/nvidia-vera-storage-benchmarks-faster-encryption-compression-integrity-checking-and-recovery-for-ai-native-storage/)

## 2. 共享 GPU 上运行隔离租户 Kubernetes 集群

【快讯内容】
NVIDIA 详解在共享 GPU 上运行隔离租户 K8s：KAI Scheduler 拓扑感知配额调度 + vCluster 每租户独立控制面/RBAC/CRD，GPU 按内核边界在 CUDA 上下文间时间片复用、MIG 提供硬件级显存硬隔离，跨组织用 VXLAN(Spectrum-X)/PKey(Quantum IB) 做逻辑网络分段。

【观点】
- **系统软件**：这是多租户 AI 工厂运行时隔离的教科书式栈——vCluster 给每团队独立控制面实现逻辑隔离而不物理切分硬件，KAI Scheduler 做分层配额/共享+突发/MIG 分区调度，GPU 时间片在内核边界切换 CUDA 上下文。对推理平台的沙箱密度、抢占与 QoS、故障域收敛有直接参考价值。
- **网络**：跨组织隔离下沉到网络层——以太网侧 VXLAN、InfiniBand 侧 Partition Key 做逻辑分段，是零信任多租户东西向微隔离的落地范式，与 Spectrum-X/Quantum 结构原生协同。
- 嵌入式边缘多租户资源分区思路间接参考。

> 参考文章：[How to Run Isolated Tenant Kubernetes Clusters on Shared GPU Infrastructure](https://developer.nvidia.com/blog/how-to-run-isolated-tenant-kubernetes-clusters-on-shared-gpu-infrastructure)

## 3. FMS 大会：NVIDIA 开源 cuFile 与 GPUDirect Storage 软件栈

【快讯内容】
FMS 大会上 NVIDIA 开源 GPUDirect Storage 的 cuFile API 及其下垂直存储软件栈——让 GPU（而非仅 CPU）直读写存储，用数十万 GPU 线程与高带宽显存微秒级安全访问数据，构建以 Linux 最佳实践为基、安全优先且 GPU-数据互操作的统一存储栈。

【观点】
- **网络**：cuFile/GPUDirect Storage 是绕开 CPU bounce buffer 的存储数据面直通路径，开源后可与 RDMA/NVLink/以太网存储访问协同，降低 AI 工厂东西向存储流量的时延与 CPU 占用，是 KV 缓存卸载与分离式服务持久层的关键底座。
- **系统软件**：开源垂直存储栈+安全优先设计，利于自建推理平台把存储访问纳入运行时安全上下文（微秒级安全访问、安全上下文随数据可达），推动全栈可审计的存储子系统。
- 嵌入式无直接参考价值。

> 参考文章：[As AI Increases Demands on Memory, Storage Steps Up](https://blogs.nvidia.com/blog/ai-storage-fms/)

## 4. Beyond VLAs：世界动作模型重塑机器人操作

【快讯内容】
NVIDIA 提出以视频世界模型替代 VLM 作为机器人策略基础的世界动作模型(WAM)：VLM 只被优化产出图像文本、不建模场景如何演化（抓取闭合、毛巾折叠、物体释放落点），WAM 让策略先学物理动力学再行动，泛化能力超越示教数据（Jim Fan「VLA 已死，世界动作模型当立」）。

【观点】
- **嵌入式**：为端侧机器人策略提供更强物理推理基座——世界模型预训练+动作微调的范式，直接影响 Jetson 级边缘操作策略的样本效率、长尾泛化与 sim-to-real，是具身智能端侧部署的方法论转向。
- **系统软件**：视频世界模型作策略底座对推理栈提出新负载（世界模型 rollout + 动作头），涉及世界模型推理与动作规划的算子/显存调度、确定性时延。
- 网络无直接参考价值。

> 参考文章：[Beyond VLAs: How World Action Models Reshape Robot Manipulation](https://developer.nvidia.com/blog/beyond-vlas-how-world-action-models-reshape-robot-manipulation)

## 5. Alpamayo 2 Super：面向自动驾驶的开放推理 VLA 模型

【快讯内容】
NVIDIA 发布 Alpamayo 2 Super：340 亿参数开放推理 VLA 模型（32B Cosmos 3 Super Reasoner + 2B 动作专家），经 RL 后训练统一轨迹生成，支持至 7 路相机 360° 环视，输出未来轨迹、因果链(Chain-of-Causation)推理迹、高层元动作、场景问答与结构化推理自动标注，可作教师模型/长尾数据策展/策略审查。

- **系统软件**：Cosmos 3 Super Reasoner + 动作专家的双模块推理栈，涉及推理编排、Chain-of-Causation 推理迹的 KV 与算子调度、RL 后训练基础设施。
