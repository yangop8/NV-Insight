## 1. cuDLA Python 绑定：Jetson AGX Orin 上原生 DLA 推理

【快讯内容】
cuda-bindings 13.3.0 新增 cuda.bindings.cudla 模块，Python 应用无需写 C++ 即可管理 DLA 设备、加载已编译网络并在 CUDA 流上提交推理，与 GPU 前后处理同流协同。Jetson AGX Orin 上 DLA 承接受支持的网络层，卸载 GPU 负载、降低功耗并释放 GPU 算力。

【观点】
嵌入式软件方向直接参考——DLA（深度学习加速器）是 Jetson 上独立于 GPU 的定点推理引擎，过去只能经 C++ TensorRT 路径调度；cuDLA Python 绑定把异构调度（GPU 预处理 → DLA 推理 → GPU 后处理）整合进单一 Python 流水线，对功耗/算力双紧的端侧多模型并发部署极具工程价值，可在不占 GPU 的前提下跑多路网络，适合机器人/车载等实时边缘场景。系统软件方向可间接留意 CUDA 流级异构协同的调度语义。

> 参考文章：[Run Native DLA Inference in Python on NVIDIA Jetson AGX Orin Using cuDLA](https://developer.nvidia.com/blog/run-native-dla-inference-in-python-on-nvidia-jetson-agx-orin-using-cudla/)

## 2. 双 DGX Station + vLLM：ConnectX-8 RDMA 托起 753B GLM-5.3 本地推理

【快讯内容】
NVIDIA 用 vLLM 把 753B 参数的 GLM-5.3（NVFP4）以张量并行 TP=2 分布到两台 DGX Station，每块 GB300 持有约半数权重；两站经 ConnectX-8 RDMA 互联，使超单卡显存的模型挂在单一 OpenAI 兼容端点后对外服务，并发 16 时吞吐峰值约 608 tokens/s。

【观点】
系统软件与网络方向双重参考——这是"桌面级多节点推理"的典型拓扑：张量并行把逐层计算切分到两卡，每步都需全归约交换激活，因此节点间互联带宽/延迟直接决定吞吐，ConnectX-8 RDMA（而非以太网 TCP）是让 TP 跨机不塌陷的关键；NVFP4 量化进一步压低显存与带宽压力。对需本地化处理敏感数据、做前沿规模模型本地原型的团队，提供了一条绕开数据中心的可复制路径。网络方向注意：RDMA + TP 对网卡与拓扑的依赖，正是 DPU/低延迟互联在端侧的价值延伸。

> 参考文章：[When One GPU Isn't Enough: Serving GLM-5.3 Across Two NVIDIA DGX Stations with vLLM](https://developer.nvidia.com/blog/when-one-gpu-isnt-enough-serving-glm-5-3-across-two-nvidia-dgx-stations-with-vllm/)
