## 1. cuBLAS 新增 FP64 仿真算法：整数 Tensor Core 加速双精度

【快讯内容】
CUDA Toolkit 13.4.2 的 cuBLAS 为 DGEMM 引入 Ozaki-II 算法、为 ZGEMM 引入 2M 方法：将双精度数拆成整数片段，在整数 Tensor Core 上相乘再重组，保持完整 FP64 精度。GB200 上 Ozaki-II DGEMM 较原生 FP64 提速 3.9x，2M ZGEMM 较原生复数 FP64 提速 5x。

【观点】
系统软件方向直接参考——这是 GPU 内核层"以整数 Tensor Core 仿真高精度"的典型路线：Blackwell 原生 FP64 吞吐被削弱后，Ozaki/2M 用误差可控的整数拆分-重组在保精度前提下换回算力，对 HPC 科学计算、线性代数库选型是重要的性能/精度权衡点，可直接改变 DGEMM/ZGEMM 密集型负载的硬件效率模型。嵌入式/网络方向无直接参考价值。

> 参考文章：[Faster Scientific Simulations with New FP64 Algorithms in NVIDIA cuBLAS](https://developer.nvidia.com/blog/faster-scientific-simulations-with-new-fp64-algorithms-in-nvidia-cublas/)

## 2. cuDLA Python 绑定：Jetson AGX Orin 原生调用深度学习加速器

【快讯内容】
NVIDIA 推出 `cuda.bindings.cudla` Python 模块，开发者无需写 C++ 即可在 Jetson AGX Orin 上原生调用 DLA（深度学习加速器）。混合模式下完成加载编译模型、在同一 CUDA 流上协调 DLA 任务与 GPU 前后处理的完整推理生命周期；面向边缘 AI，将网络推理从 GPU 卸载到 DLA 以省电，同一 API 亦适用 RTX Spark。

【观点】
嵌入式软件方向直接参考——把 DLA 这一专用定点加速器从 C++ 下沉到 Python，大幅降低端侧异构推理的工程门槛：DLA+GPU 分工（DLA 跑稳定网络主体、GPU 做前后处理）是 Jetson 功耗/热受限场景的核心优化手段，Python 化利于快速部署与量化模型落地。系统软件方向间接——涉及 CUDA 流级任务编排与异构调度。网络方向无直接参考价值。

> 参考文章：[Run Native DLA Inference in Python on NVIDIA Jetson AGX Orin Using cuDLA](https://developer.nvidia.com/blog/run-native-dla-inference-in-python-on-nvidia-jetson-agx-orin-using-cudla/)

## 3. 双 DGX Station 跨节点用 vLLM 服务 GLM-5.3

【快讯内容】
NVIDIA 演示在两台 DGX Station（各 1 块 GB300 GPU）上以 vLLM、张量并行 TP=2、经 ConnectX-8 RDMA 链路服务 7530 亿参数 GLM-5.3（NVFP4）。约 464GB 权重超单卡 252GB 显存，故每卡持有并计算约一半权重，统一 OpenAI 兼容端点对外；叠加多 token 预测、FP8 KV 缓存与前缀缓存，编码提示基准并发 16 时峰值约 608 tokens/s。

【观点】
系统软件方向直接参考——完整示范"显存不足即跨节点 TP"的推理工程范式：NVFP4 权重 + FP8 KV 缓存 + 前缀缓存 + MTP 的组合拳，是单机放不下的超大模型在小型工作站集群落地的关键配方，对 vLLM 部署与并发调优有直接借鉴。网络方向直接参考——TP=2 把每步计算暴露在节点间通信路径上，ConnectX-8 RDMA 的低延迟高带宽是吞吐不塌陷的前提，印证互连即推理性能瓶颈。嵌入式方向无直接参考价值。

> 参考文章：[When One GPU Isn't Enough: Serving GLM-5.3 Across Two NVIDIA DGX Stations with vLLM](https://developer.nvidia.com/blog/when-one-gpu-isnt-enough-serving-glm-5-3-across-two-nvidia-dgx-stations-with-vllm/)

## 4. SOMA Retargeter：人体动作向人形机器人的开源重定向

【快讯内容】
NVIDIA 开源 SOMA Retargeter，将基于共享 SOMA 骨架的人体动作数据重定向到特定人形机器人的比例与关节结构：先缩放动作，再用 Newton 与 NVIDIA Warp 求解逆运动学，并做足部着地等修正；输出机器人根位姿与关节角 CSV，可直接喂给动作跟踪策略训练。v0.2 含 5 款人形机器人参考配置。

【观点】
嵌入式软件方向直接参考——动作重定向是人形机器人从"人类示范数据"到"可执行策略"的关键中间件，足部着地修正等直击 sim-to-real 落地痛点，CSV 输出对接策略训练流水线利于端侧部署闭环。系统软件方向间接——IK 求解建立在开源物理引擎 Newton + Warp 之上，延续 NVIDIA 以 Newton 统一机器人仿真底座的路线。网络方向无直接参考价值。

> 参考文章：[Adapt Human Motion for Robots with NVIDIA SOMA Retargeter](https://developer.nvidia.com/blog/adapt-human-motion-for-robots-with-nvidia-soma-retargeter/)

## 5. cuPhoton 做黑洞干涉测量：GPU 关联器加速 VLBI

【快讯内容】
cuPhoton.xBeam 是 GPU 关联器，将事件视界望远镜（EHT）的射电记录转为可见度数据（后续重建黑洞图像所用测量量）。在 Vera Rubin NVL72（64 GPU）系统上，按观测时间分片到各 GPU，70 秒处理 10TB 数据集，较 x86 CPU 基线约快 460 倍。

【观点】
系统软件方向间接参考——典型的"超大科学数据集按维度分片 + 多 GPU 并行关联"范式，460x 加速凸显数据密集型科学工作流在 NVL72 规模化系统上的吞吐优势，对多 GPU 任务切分与 I/O 编排有一定借鉴。网络方向间接——10TB 级 VLBI 数据的 GPU 间分发依赖高带宽互连（NVL72 NVLink 域）。嵌入式方向无直接参考价值；整体与三方向关联偏弱，登记备查。

> 参考文章：[Run GPU-Powered Black Hole Interferometry with NVIDIA cuPhoton](https://developer.nvidia.com/blog/run-gpu-powered-black-hole-interferometry-with-nvidia-cuphoton/)
