## 1. NVIDIA Run:ai 全面开源，纳入 DSX AI 工厂平台

【快讯内容】
NVIDIA 将 Run:ai 平台全面开源并纳入 DSX AI 工厂平台，含四个可独立采用的模块：KAI Scheduler（GPU 感知的 Kubernetes 调度，CNCF Sandbox 项目、Apache 2.0）、GPU Fractioning Operator（CUDA 原生 GPU 切分共享）、KAI Resource Management（组织级配额与层级）、Workload Map，社区版无需付费订阅；Crusoe、Mirantis、Nebius、Rafay、Saturn Cloud 等 8 家生态伙伴接入，配套 Model Streamer、Grove。

【观点】
系统软件：直接命中多节点/多租户 GPU 调度与资源管理的核心控制面——GPU 感知调度、CUDA 原生细粒度切分（单卡多工作负载隔离共享）、配额层级与工作负载编排开源化后可被自研基础设施直接复用并二次开发，对集群调度器、GPU 利用率优化与推理/训练作业编排有直接参考；网络：多租户 AI 工厂下调度与资源隔离须与网络 QoS/拓扑感知放置联动，Grove 对多组件推理服务的编排触及东西向通信调度，间接参考；嵌入式无直接。

> 参考文章：[NVIDIA Run:ai Is Now Open Source as Part of NVIDIA DSX AI Factory Platform](https://developer.nvidia.com/blog/nvidia-runai-is-now-open-source-as-part-of-nvidia-dsx-ai-factory-platform/)

## 2. 用 AI 智能体重写 Apache Spark UDF 实现 GPU 加速

【快讯内容】
NVIDIA 介绍用 AI 编码智能体把 Spark UDF 重写为 GPU 可执行形态（配合 cuDF 插件）：不透明 UDF 迫使 Spark 回退到逐行执行、阻断 GPU 加速；给出三条改写路径——Spark SQL 表达式（简单逻辑）、RapidsUDF/cuDF 列式实现（复杂列运算）、JNI 调用自定义 CUDA 内核（最难场景）。开源 cuDF skills 引导智能体做测试生成、转换、基准、剖析优化闭环校验正确性，某消费科技公司转换 30+ 生产 UDF，单算子从 274.55 小时降至 12.78 小时（6000 亿行）。

【观点】
系统软件：把「GPU 内核开发/算子移植」交给带正确性反馈闭环的 AI 智能体，延续可验证运行时工程范式——先生成 CPU 行为测试锁定语义、再产 GPU 实现、基准+剖析迭代，关键在正确性校验而非盲目生成，对自研 CUDA 内核/列式算子迁移、RAPIDS 加速数据管道有直接参考；逐行→列式/向量化的回退根因分析，对任何向量化查询引擎的算子优化均有借鉴，网络/嵌入式方向关联较弱。

> 参考文章：[How to Rewrite Apache Spark UDFs for GPU Acceleration with AI Agents](https://developer.nvidia.com/blog/rewrite-apache-spark-udfs-gpu-acceleration-ai-agents)
