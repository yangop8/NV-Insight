## 1. Agent Substrate：面向规模化智能体的 Kubernetes 运行时

【快讯内容】
NVIDIA 在 KubeCon NA 2026 推出开源 Agent Substrate 并捐赠 CNCF Sandbox：在少量 worker Pod 上运行海量智能体会话，空闲会话从沙箱（gVisor / microVM）快照换出并释放 worker，再恢复到任一空闲 worker；与 Dynamo 推理、KAI Scheduler 协同。

【观点】
系统软件方向直接参考——这是"会话级快照+抢占式复用"的运行时调度范式：把智能体会话当可挂起/迁移的轻量执行体，用沙箱隔离（gVisor/microVM）换取多租运行时安全，worker 池化显著提升 GPU/CPU 利用率，对构建高密度、长尾空闲的 Agent 平台有直接工程价值。网络方向间接——会话迁移要求低延迟状态同步与一致性拓扑感知调度。

> 参考文章：[Agent Substrate: Advancing Kubernetes for Agents at Scale](https://developer.nvidia.com/blog/agent-substrate-advancing-kubernetes-for-agents-at-scale/)

## 2. NVIDIA Snapshot：秒级启停 GPU 工作负载

【快讯内容】
NVIDIA 开源 Snapshot——面向 Kubernetes GPU 工作负载的检查点/恢复系统，捕获完整初始化后的 CPU 与 GPU 显存状态。以 PodSnapshot CRD 对运行 Pod 打快照、新 Pod 以注解触发恢复，官方基准推理副本上线 3.6~42.7 秒，较冷启动提速 8x~36x。

【观点】
系统软件方向直接参考——GPU 显存级检查点是推理冷启动与弹性伸缩的关键瓶颈，Snapshot 以 Kubernetes 原生 CRD（PodSnapshot/注解恢复）把"进程+显存快照"工程化，对大模型副本快速扩缩容、抢占恢复、故障快速拉起意义重大；与 Agent Substrate 的会话换出共用同一快照底座，构成 NVIDIA K8s 运行时弹性的核心能力。嵌入式/网络方向间接。

> 参考文章：[Start and Restore GPU Workloads in Seconds with NVIDIA Snapshot](https://developer.nvidia.com/blog/start-and-restore-gpu-workloads-in-seconds-with-nvidia-snapshot/)

## 3. NVIDIA Kubernetes Engine（NVKE）与 Kubernetes Recipes（NVKR）

【快讯内容】
NVIDIA 开源 NVKE，让 AI 工厂在自有 GPU 基础设施上对外提供托管 Kubernetes 集群（API 置备与管理）；配套 NVKR 从版本锁定来源、经校验的软件与 GPU 代次组合构建节点/容器镜像与软件包。二者 Apache 2.0、公开预览，属 DSX AI Factory Platform 组件，暂不建议生产。

【观点】
系统软件方向直接参考——NVKE/NVKR 把"GPU 托管 K8s 即服务"拆成置备 API 与可复现镜像供应链两层：租户隔离、升级、恢复、硬件/网络/驱动资质校验被产品化，版本锁定+校验组合直击 GPU 栈"驱动-固件-CUDA-K8s"兼容性漂移痛点。网络方向间接——多租集群须在置备层绑定网络资质与隔离策略。

> 参考文章：[Manage Kubernetes Clusters for GPU Infrastructure with NVIDIA Kubernetes Engine](https://developer.nvidia.com/blog/manage-kubernetes-clusters-for-gpu-infrastructure-with-nvidia-kubernetes-engine/)

## 4. Alpamayo 2 Edge：DRIVE AGX Thor 上的车载推理模型

【快讯内容】
NVIDIA 发布 Alpamayo 2 Edge——20 亿参数视觉-语言-动作驾驶模型，实时跑在 DRIVE AGX Thor：输入环视视频、导航与自车历史，输出推理轨迹，仅在复杂场景触发推理。由 Alpamayo 2 Super 蒸馏、闭环 RL 后训练，经量化、TensorRT 引擎与 DFlash2 投机解码优化，达 160~190ms 像素到轨迹时延。

【观点】
嵌入式软件方向直接参考——这是安全关键车载嵌入式推理的完整落地样板：蒸馏（20亿参数）+量化+TensorRT+投机解码（DFlash2）在 Thor 功耗-散热包络内把端到端时延压到 160~190ms，"按需推理"进一步省算力；对端侧大模型部署的内存/时延优化极具参考。系统软件方向间接——闭环 RL 后训练与 AlpaJudge 评测构成可复现安全验证闭环。

> 参考文章：[Running AV Reasoning Models Within Onboard Compute and Latency Limits](https://developer.nvidia.com/blog/running-av-reasoning-models-within-onboard-compute-and-latency-limits/)

## 5. Holoscan 5 构建机械臂重力补偿实时控制环（回溯补录 11-09）

【快讯内容】
NVIDIA 教程用 Holoscan 5 + Pinocchio（逆动力学）+ motorbridge 为 Seeed reBot Arm B601-DM 搭重力补偿环：三个自定义算子（400Hz 读关节、算重力矩、发电机指令）经 partition 绑同一线程、drop-oldest 队列防陈旧样本。控制 partition 绑定 CPU 核后，p99.99 时延 C++ 降约 5x、Python 降约 9.6x（Nsight 实测），在 Jetson Orin Nano/Thor 与 x86 验证。

【观点】
嵌入式软件方向直接参考——这是实时控制环确定性调度的教科书级实践：Holoscan partition 线程绑定 + CPU 核亲和消除抖动、drop-oldest 保证时效性，p99.99 尾延迟数量级下降，正是安全关键实时系统（400Hz 控制环）所需；跨 Jetson Orin Nano/Thor 到 x86 的可移植性对边缘机器人部署友好。系统软件方向间接——CPU 亲和/分区线程模型是通用实时调度优化范式。

> 参考文章：[Make a Robot Arm Feel Weightless with NVIDIA Holoscan 5](https://developer.nvidia.com/blog/make-a-robot-arm-feel-weightless-with-nvidia-holoscan-5/)
