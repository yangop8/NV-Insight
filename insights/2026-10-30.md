## 1. 用 Tensor Core 低精度 GEMM 加速 MLIP 推理：BF16x9 / TF32x3 "免重训"换吞吐，精度不变

【快讯内容】
NVIDIA 发文介绍用 Tensor Core 低精度 GEMM 路径加速机器学习原子间势（MLIP）推理：多数 MLIP 仍以 FP32 推理、未吃到新 GPU 的低精度矩阵算力。BF16x9（Blackwell）在 B300 上使 PET 模型主要 GEMM 提速达 2.5x、整步 1.7x；TF32x3（Ampere）在 A100 提速约 1.7~1.9x。两条路径均无需重训或改架构，结构弛豫步数/精度基本不变。

【观点】
系统软件方向直接参考——正中「推理引擎内核优化」与「系统级性能分析与优化」：BF16x9 / TF32x3 本质是**用多趟低精度 Tensor Core 矩阵乘拼出接近 FP32 的数值精度**（误差补偿式 GEMM 仿真），把长期停留在 FP32、跑在 CUDA Core 上的科学计算负载迁移到 Tensor Core 低精度高吞吐通路，而代价只是算法层面的多趟累加、无需触碰模型权重或网络结构。对自研推理/HPC 栈的启示有三：①它是 **cuBLAS 级别的 drop-in 替换**（opt-in 选路），同一手法可外推到任何"精度敏感但当前 FP32-bound"的 GEMM——不止 MLIP，也包括物理仿真、线代内核乃至开源物理引擎 Newton 类工作负载；②它提供了"低精度换吞吐"在**不可容忍精度回退**场景下的范式——通过 3 趟 TF32 / 9 趟 BF16 的误差补偿把精度拉回 FP32 水位（弛豫 218 步 vs TF32x3 的 218~222 步即为佐证），与纯 FP8/BF16 量化"以精度换速度"形成互补的另一条技术路线；③它再次说明 Blackwell（BF16x9）与 Ampere（TF32x3）需各自匹配不同的拆分策略，内核选路要感知架构代际与 Tensor Core 能力。嵌入式方向间接参考——同类 FP32→Tensor Core 误差补偿思路对端侧/Jetson 上精度敏感的科学推理有借鉴，但本文基准面向 B300/A100 数据中心 GPU、未涉端侧。网络方向——本篇为单卡计算内核优化，无直接网络内容。（注：BF16x9/TF32x3 的 2.5x/1.7x/1.7~1.9x 提速与弛豫步数数字出自官方博文及 Blockchain.News 交叉核对，具体以 cuBLAS 与博文官方发布为准。）
