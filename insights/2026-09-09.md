## 1. Introducing CUDA Rust：两条轨道用 Rust 写 GPU 内核

【快讯内容】
developer 博客（09-08 发布，配合 RustConf 2026）推出 CUDA Rust，让 GPU 内核用 Rust 原生编译到 PTX，分两条与 CUDA 对应的轨道：SIMT 轨（cuda-oxide，自定义 rustc codegen 后端经 Pliron IR + LLVM 直出 PTX）与 Tile 轨（cutile-rs，经 Tile IR JIT，由编译器管理线程映射与内存布局）。两者在编译期强制内存安全——cuda-oxide 用 DisjointSlice + launch 契约防别名，cutile-rs 用张量分区 + 所有权保证独占访问。

【观点】
系统软件方向直接参考：把 Rust「编译期内存安全 + 所有权」模型下沉到 GPU 内核层，是驱动/运行时之上内核工程化的范式补充——DisjointSlice/launch 契约与张量分区在编译期消除别名与数据竞态，可为 vLLM/SGLang/TensorRT-LLM 等推理内核提供比手写 CUDA C++ 更强的正确性保证与可维护性；原生编译到 PTX（非 FFI 包装）意味着可纳入既有编译/调优流水线，与此前追踪的 Modern CUDA Toolbox「Sanitizer→Nsight→CUB」方法论互补（本篇在语言层前移安全，后者在实现层调优）。嵌入式方向直接参考：Rust 的编译期安全对 Jetson/边缘安全关键系统（safety-critical）尤具价值——无 GC、零成本抽象 + 内核级内存安全，利于端侧实时内核的认证与可审计。网络方向无直接参考价值。

> 参考文章：[Introducing CUDA Rust: Two Tracks for Writing GPU Kernels](https://developer.nvidia.com/blog/introducing-cuda-rust-two-tracks-for-writing-gpu-kernels)

## 2. 如何为 AI 推理与 TCO 合理选型 GPU（回溯补录）

【快讯内容】
developer 博客（09-01 发布/topic 382024，低于 09-02 追踪的 382029，属漏捕回溯补录）给出一套按真实负载而非拍脑袋为推理选型 GPU 的框架：以用例、token 模式、时延目标、并发、缓存命中率、模型选择与部署策略为输入，结合「核心容量 + 弹性容量」规划、GPU 右选型，以及量化/剪枝/蒸馏等模型优化，在压低 TCO 的同时保住性能；并强调用本地容量与云弹性配比来吸收负载波动、避免过量采购。

【观点】
系统软件方向直接参考：把「时延目标 / 并发 / KV 缓存命中率 / token 模式」作为推理容量规划的一等输入，与调度器（gang scheduling、拓扑亲和、功率-DVFS）和模型优化（量化/剪枝/蒸馏）联动，是把每 token 成本落到工程选型的可复现方法论，可与此前追踪的 Vera Rubin 每瓦性能三联指标、DSX MaxLPS 供电边界调度、Shadow Engine 秒级恢复共同纳入容量-成本模型。网络方向间接参考：并发与部署策略（本地 + 云弹性）决定东西向集合通信与跨域流量规模，选型需与 Spectrum-X/NVLink scale-up 带宽联合规划。嵌入式方向间接参考：量化/剪枝/蒸馏同为端侧受限算力-显存包络下的核心手段。

> 参考文章：[How to Size GPUs for AI Inference and TCO Without Overspending](https://developer.nvidia.com/blog/how-to-size-gpus-for-ai-inference-and-tco-without-overspending)
