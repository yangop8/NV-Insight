## 2. Reshard 集合通信原语加速 RL 权重刷新

【快讯内容】
NVIDIA 发布 Reshard 集合通信原语优化强化学习权重刷新：把 refit 重构为 DTensor→DTensor 张量布局传输、仅传理论最小数据；开源 NCCL M2N Reshard，集成 NeMo RL，H100/GB200 实测较 gather-broadcast 提速 2.7~5.7x。

【观点】
系统软件方向直接参考——正中「多节点调度 + 推理引擎内核优化」：RL 训练每轮需把训练副本权重刷新到推理副本（最大开源权重模型单次约 10TB），传统 gather-and-broadcast 冗余巨大；Reshard 以设备网格 + 分片放置描述源/目的布局，只搬每个推理 GPU 真正需要的张量区域，把 refit 从「聚合-广播」降为「布局重分片」。混合设计对占参数约 95% 的前馈投影走 Reshard、对 QKV 等小权重仍走常规路径，工程取舍务实。参考实现开源于 NVIDIA/nccl-extensions，对自研 RLHF/RL 训练栈的权重同步、训推一体编排有直接借鉴。网络方向间接——10TB 级跨副本传输直接压在 NVLink/东西向 fabric 上，布局感知的最小传输本质是对集合通信流量的源头削减。

> 参考文章：[Accelerating Reinforcement Learning Weight Refit with the Reshard Collective](https://developer.nvidia.com/blog/accelerating-reinforcement-learning-weight-refit-with-the-reshard-collective)

## 4. Vera CPU：面向智能体的高吞吐 + 最快执行

【快讯内容】
NVIDIA 博文主打 Vera CPU「高吞吐 + 最快智能体」：100MW 数据中心建模较最快 x86 每瓦多 1.6x 智能体、较最省电 x86 快 2x；Daytona 10.8s 内起 1000 个代理沙箱（x86 需 88.4s），DeepInfra 独立实测领先但幅度更温和。

【观点】
系统软件方向直接参考——正中「运行时安全（沙箱/进程隔离）+ 系统级性能」：Vera 以 Olympus 核强调单线程性能，对应智能体工作负载大量串行编排/工具调用而非纯并行吞吐；Daytona「10.8s 起 1000 个沙箱 vs x86 88.4s」直指代理沙箱冷启动/进程隔离的系统级瓶颈，对自研 Agent 运行时（本地 LLM + 多子代理 + 沙箱）的调度与隔离开销有直接参考，与 11-05 AI Factory Operations Agent（本地 Nemotron + OpenShell 沙箱）运维主线呼应。独立核验（DeepInfra）显示 Vera 对 x86 领先确凿但较官方口径幅度更小（约 1.2~1.76x），引用时宜以中性口径。网络间接——高密度代理沙箱加剧东西向调用/服务网格压力。嵌入式间接——Vera 属数据中心 CPU，端侧无直接产品，但「为串行代理优化单线程」思路对边缘实时调度有方法论借鉴。
