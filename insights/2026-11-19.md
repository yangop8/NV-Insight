## 1. 稀疏注意力软硬协同：长上下文推理 indexer 成新瓶颈

【快讯内容】
NVIDIA 技术博文解析模型级稀疏注意力的长上下文推理优化：query 仅关注学习到的 key 子集，但为所有 key 打分的 indexer 开销居高——DeepSeek V3.2 在 128K 下 indexer+Top-k 占 prefill 层时间 47%。给出 FP8 indexer 核与 8 条调参准则（单 key head、Tensor Core tile 内约 200 行、FP16 epilogue 解码快约 1.3×）。

【观点】
系统软件方向直接。随上下文拉长，推理瓶颈从核心注意力转向"打分+选择"路径，kernel 层需把 indexer 量化到 FP8、Top-k 与 indexer 融合、复用上一步选择，并用 TensorRT-LLM 的 Guess-Verify-Refine Top-k（较 radix select 快 2.1~2.4×）、FlashInfer 融合选择核。印证推理引擎优化正从"算得快"走向"选得省"，长上下文智能体的有效吞吐取决于稀疏结构与硬件 tile 的协同设计。

> 参考文章：[Co-Designing Sparse Attention for Efficient Long-Context Inference](https://developer.nvidia.com/blog/co-designing-sparse-attention-for-efficient-long-context-inference/)

## 2. Slurm 26.11 HRES：把 QPU 当集群级原生资源调度

【快讯内容】
Slurm 26.11 引入 Hierarchical Resources（HRES）插件，可将量子处理器（QPU）作为集群级原生资源调度——QPU 是全集群加速器而非节点私有，旧的 GRES/license+SPANK 变通会让计算节点空等。HRES 用 resources.yaml 定义资源与可用节点绑定，插件为一段 Lua 脚本（健康检查/准入/异步预留/释放），不链接 libslurm、升级免重编。用户以 `--resources=qpu:1[shot=1000]` 申请。

【观点】
系统软件方向直接——多节点/异构资源调度。HRES 把"非节点绑定的共享加速器"抽象为一等调度单元，解决传统 GRES 节点粒度与真实硬件拓扑不匹配的老问题，这一思路对任何集群级共享设备（池化显存、DPU、光交换资源）都有借鉴意义。Lua 插件与 libslurm 解耦的设计降低了运维升级成本，QRMI/QDMI 已开源插件、多家量子厂商跟进，标志 HPC 调度器正向"量子-经典混合"资源模型演进。

> 参考文章：[Integrating QPUs into Supercomputing Centers Using Slurm HRES Plugins](https://developer.nvidia.com/blog/integrating-qpus-into-supercomputing-centers-using-slurm-hres-plugins/)

## 3. Eclypsium×BlueField：以独立安全边界"验证基础设施、强制 AI 执行"（10-29 补录）

【快讯内容】
NVIDIA 与 Eclypsium 合作，以"验证信任"取代"假定信任"保护 AI 基础设施。BlueField DPU 提供硬件级认证启动、硬件隔离、固件安全更新、回滚保护与设备证明；Eclypsium AI Infrastructure Assurance 对照已知良好基线核验固件/硬件、检测 OS 之下的漂移与未授权改动。运行时侧 NVIDIA Sentry（基于 BlueField-4、OpenShell 参考架构）做带外监控与芯片内策略强制。

【观点】
网络 + 系统软件方向双重直接。安全边界下沉到 DPU/带外路径，是零信任在 AI 工厂的硬件化落地：BlueField 作为独立信任根，把固件完整性、租户隔离与运行时策略从被监控的主机 OS 中剥离，避开"用被攻陷系统自证清白"的死结。供应链/生命周期视角（硬件重分配前复核）呼应 AIBOM、运行资产可审计主线；Sentry 入 OpenShell 参考架构，预示 DPU 将成为数据中心安全与网络策略执行的统一落点。

> 参考文章：[Building Trusted AI Infrastructure for Safe and Secure AI](https://blogs.nvidia.com/blog/eclypsium-trusted-safe-secure-ai-infrastructure/)

## 4. RTX Spark 紧凑台式机上市：本地 120B 推理 + 10GbE 入网

【快讯内容】
NVIDIA RTX Spark 紧凑台式机正式开售（ASUS/Dell/MSI，Acer/GIGABYTE/HP 及 Microsoft Surface RTX Spark Dev Box 后续跟进）：20 核 Grace CPU + Blackwell GPU（6144 CUDA 核）、最高 128GB 统一内存、最高 1 PFLOPS AI 算力，配 10GbE 以太网搬运大数据集/模型。定位"专用 Windows PC"跑本地模型与常驻智能体，可本地运行 120B LLM，支持 CUDA/WSL/Hermes Agent/Unsloth 微调。

【观点】
嵌入式 + 网络方向。统一内存 + 本地 1 PFLOPS 把 120B 级推理下沉到桌面端侧，延续本地 AI "数据不出域、免按 token 计费"范式，与 DGX Spark/RTX Spark 笔记本批次一脉相承；对端侧垂域小模型微调与常驻智能体部署是低门槛原型平台。10GbE 内置反映端侧节点"入网搬运数据集/模型"已成标配，互联带宽是本地到集群平滑放大的关键一环。属产品上市公告，技术实质为既有平台延伸。

> 参考文章：[NVIDIA RTX Spark Compact Desktops Out Now](https://blogs.nvidia.com/blog/rtx-spark-desktop-local-ai-available-now/)
